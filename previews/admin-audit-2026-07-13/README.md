# 师行后台整合审阅（2026-07-13）

## 结论

将 `dashboard.html` 的经营概览并入 `admin.html`，保留一个后台入口。推荐以 `/admin.html` 为唯一地址，`/dashboard.html` 重定向到 `/admin.html#overview`。

## 当前分工

- `dashboard.html`：总收入、本月收入、订单、注册、收入趋势、使用趋势、广播/评语/作文批改/作文学习产品概览、作文学习续费、最近支付和注册。
- `admin.html`：用户、密码重置、反馈、功能订阅、评语使用、统一邀请审核、积分调整、广播开通、作文学习续费。

## 主要问题

1. 两套登录状态不一致：数据仪表盘把管理员密码本身存进 `localStorage`，管理后台只存在内存；从仪表盘进入管理操作还要重新登录。
2. 两页都拉用户列表、都能做作文学习续费，职责已经交叉。
3. 数据口径漂移：仪表盘仍显示旧的分产品邀请统计，管理后台已经使用统一邀请体系。
4. 产品覆盖不完整：仪表盘没有思想圆桌、数学课件和统一师行积分的完整经营数据。
5. 管理后台一次并发加载多个接口，任一接口失败都可能被误报成“密码错误”。
6. 用户列表无分页，用户增长后加载和操作都会变慢。
7. 高风险操作依赖 `prompt/confirm`，缺少操作记录、理由字段和二次确认摘要。
8. 服务端存在两组重复的 `/api/admin/activate` 和 `/api/admin/reset-password` 路由。
9. 广播后台按钮写“开通年费”，而当前售卖口径是半年会员。
10. 已有作文、思想圆桌的后台接口没有出现在任何后台页面中。

## 推荐信息架构

1. 概览：收入、订单、用户、各产品使用量、异常提醒。
2. 用户：搜索、筛选、用户详情、积分、广播会员、使用记录、邀请关系、支付记录。
3. 财务：订单、充值、退款状态、奖励冲正。
4. 产品：广播、评语、作文、思想圆桌、数学课件、作文学习分别查看数据和配置。
5. 邀请：点击、注册、激活、付费、待审核、冲正。
6. 客服：密码重置、反馈、功能订阅。
7. 系统：管理员操作日志、关键配置、服务状态。

## 实施顺序

- P0：统一入口和登录；合并概览；统一邀请口径；清理重复路由和错误套餐文案。
- P1：用户详情页、订单页、产品数据补齐、接口局部失败提示、分页搜索。
- P2：操作审计、异常提醒、导出和经营漏斗。

## 证据限制

线上页面可访问，但当前浏览器截图通道超时，未进入需要管理员密码的登录后界面。功能结论来自本次线上可达性检查以及生产同版本的 `public/dashboard.html`、`public/admin.html` 和 `server.js`。
