# 教室广播与班级积分一体化设计

## 背景

教室广播和班级加扣分都属于需要在教室电脑上长期打开的工具。若继续保留两个独立页面，班级需要重复绑定、反复切换页面，还要分别维护班级与学生数据；若把积分座位表强行常驻，又会让只使用广播的任课教师感到臃肿，也会让学生在日常课堂中持续关注座位和排名。

本设计把现有教室端升级为一个网址、一个班级绑定、多个工作模式的“班级大屏”。广播仍是基础能力，班级积分是按班级主动开启的可选模块。

## 目标

- 一个教室只常驻打开一个页面，同时承载日常信息、广播与可选的班级积分。
- 保持现有广播用户的界面和使用习惯；未开启班级管理的班级完全看不到积分入口。
- 教室端和教师端都能加扣分，所有变动进入同一套可追溯流水。
- 日常状态保持安静，不常驻显示座位表、学生分数或排行榜。
- 广播在任何页面都拥有最高优先级，播报结束后准确恢复原状态。
- 校园网络短暂中断时不丢失教室端登记记录。
- 班级积分随广播订阅提供，不按登记次数消耗师行积分。

## 不在第一阶段范围内

- 考试成绩导入与分析。
- 学生个人成绩雷达和长期学业趋势。
- 小组管理、奖品兑换等扩展激励功能。
- 从旧班级管理平台自动迁移历史考试数据。
- 学生端账号或学生自助查看页面。

这些功能放在第二阶段，并复用本阶段建立的班级、学生和积分基础数据。

## 方案选择

### 方案 A：同一大屏、多种模式（采用）

一个绑定页面内部切换日常、积分登记、排行榜和流水模式。广播使用最高层覆盖，结束后恢复进入广播前的模式。

优点是班级只绑定一次，数据与在线状态天然共用，广播抢占和恢复逻辑清晰；缺点是需要把现有单一空闲页改造成明确的状态容器。

### 方案 B：广播与积分两个页面互相跳转

改动局部，但页面切换时要额外解决广播实时连接、班级上下文与未提交操作，长期使用仍有割裂感。

### 方案 C：在广播页上叠加积分侧栏

开发量较小，但座位表、规则、排行榜和流水会挤在有限侧栏内，不适合教室投影和连续登记。

## 产品原则

1. **按班级启用，不按教师身份判断。** 同一位教师可能在不同班级承担不同角色，系统不询问“是否班主任”。
2. **操作频率不等于展示频率。** 积分登记很常用，但座位表和排行榜不应长期面对全班展示。
3. **流水是事实来源。** 不单独维护一个可被任意改写的总分；所有总分和排名都由不可变流水汇总。
4. **教室端优先简洁。** 班干部无需登录、选择登记人或输入操作码。
5. **广播优先。** 积分操作不能阻塞通知到达和语音播报。

## 班级模式

每个班级增加独立的班级管理开关：

- 新班级与现有班级默认均为“仅广播”。
- 班级创建者可在教师端开启“班级管理”。
- 开启后，教师端与对应教室大屏才显示加扣分、积分榜、流水、学生名单、座位表和规则设置。
- 关闭时只隐藏功能，学生、规则、周期与历史流水全部保留。
- 同一教师名下不同班级可以采用不同模式。
- 班级协作教师看到的模块由班级开关决定，不由其账号角色决定。

## 教室大屏状态

### 1. 日常常驻页

保留现有班级名称、时钟、日期、联网状态、公告、作业、值日和临时提醒。开启班级管理后，在不干扰主要信息的位置增加三个入口：

- 加扣分
- 积分榜
- 流水记录

日常页不展示座位表、学生积分、具体积分变动或排名；最多显示“今日积分变动 N 次”这类班级级别的轻量信息。

### 2. 积分登记页

- 进入后全屏展示当前班级座位表。
- 学生卡片只显示姓名和当前周期积分。
- 点击学生后，在右侧或就近区域显示已配置的加分、扣分规则。
- 点击规则立即入账，不弹二次确认，不唤起键盘。
- 操作成功后，学生卡片短暂高亮并显示规则与分值。
- 支持连续登记；每次有效操作都重新开始无操作计时。
- 提供次要的“批量登记”入口，可选择多名学生应用同一规则。
- 页面展示最近 5 条操作与“撤销上一笔”。

积分登记页连续 **60 秒**没有点击、触摸或键盘操作后，自动返回日常页。

### 3. 积分榜

排行榜可查看今日、本周、本月和本学期统计。它是主动进入的查看页，不在日常状态常驻；60 秒无操作后返回日常页。

### 4. 流水记录

教室端默认展示当天流水，可按学生以及加分、扣分筛选；60 秒无操作后返回日常页。教师端提供完整历史与更多筛选条件。

### 5. 广播覆盖层

- 广播可从上述任何状态进入，拥有最高显示和音频优先级。
- 覆盖前保存当前大屏模式及必要的界面上下文。
- 已经完成的积分登记不会因广播覆盖而丢失。
- 多条广播继续使用现有队列依次播放。
- 播报结束后恢复原模式；若恢复到积分、排行榜或流水页，重新开始 60 秒计时。
- 广播历史与积分流水分别保存和展示。

## 积分反馈与声音

- 默认只使用卡片高亮、数字动画和非阻塞提示，不朗读学生姓名、分值或扣分原因。
- 提供班级级别的统一“积分操作提示音”开关，默认关闭。
- 积分提示音不得打断正在播放的广播；广播开始时应立即停止或抑制积分提示音。

## 双端登记

### 教室端

- 无账号登录、操作码或登记人选择。
- 流水来源统一显示为“教室端登记”。
- 主要供班干部在已绑定的教室设备上登记。

### 教师端

- 登录教师可远程为自己有权限访问的班级登记。
- 流水来源统一显示为“教师端登记”。
- 产品界面不展示具体登记人；服务端可保留认证用户 ID 用于安全审计，但不作为班级流水的用户可见字段。

教室端与教师端的记录进入同一流水，彼此不覆盖，按独立操作累计。

## 撤销与流水语义

- 每次加扣分都是一条不可变记录。
- 记录包含班级、学生、积分周期、规则、规则名称快照、分值、来源端、创建时间和唯一操作编号。
- 批量登记为每名学生创建独立流水，并使用批次编号关联。
- “撤销”不删除或修改原记录，而是创建一条数值相反并指向原记录的新流水。
- 同一原记录只能被成功撤销一次。
- 排行榜与学生积分通过所选周期内全部有效流水求和，原记录与反向记录自然抵消。
- 来源端只向用户显示“教室端登记”或“教师端登记”。

## 积分周期

- 原始流水永久保留，不通过清空总分开启新周期。
- 系统支持今日、本周、本月和本学期统计。
- 开启新学期时创建新的积分周期，旧周期转为历史状态并保持可查询。
- 一个班级同一时间只能有一个当前学期周期。
- 未显式创建周期时，首次开启班级管理自动创建默认当前学期。

## 教师端信息架构

现有教师端扩展为四个主要区域，不另建一套独立后台：

1. **发广播**：保留即时通知、公告、模板和预览。
2. **积分管理**：远程加扣分、排行榜和完整流水。
3. **班级管理**：学生名单、座位表、积分规则、积分周期、协作教师和班级管理开关。
4. **我的**：账号、订阅和个人设置。

教师端修改学生、座位或规则后，通过实时事件通知已绑定大屏刷新；无需重新绑定或手动刷新。

## 收费与权益

- 班级管理模块包含在现有教室广播订阅中。
- 加扣分、排行榜、流水和座位表不限次数，不消耗师行积分。
- 仅广播用户保持原有订阅与界面，不需要为隐藏的积分功能二次付费。
- 试用期和会员有效期沿用现有广播规则。
- 会员到期后保留数据与历史查看能力；广播发布、积分登记和配置修改进入只读限制，并给出明确续费提示。

## 数据设计

在现有 `classes`、`class_members`、`notifications` 和 `bulletins` 基础上扩展：

### classes

新增：

- `management_enabled`：是否开启班级管理，默认 0。
- `archived_at`：班级归档时间。已有积分流水的班级不直接物理删除。

### class_students

- `id`
- `class_id`
- `name`
- `student_no`（可选）
- `seat_row`、`seat_col`
- `archived`
- `created_at`、`updated_at`

学生归档后不再出现在登记页，但历史流水继续关联同一学生 ID，避免同名或改名污染统计。

### class_score_rules

- `id`
- `class_id`
- `name`
- `delta`
- `sort_order`
- `active`
- `created_at`、`updated_at`

流水保存规则名称和分值快照，因此后续修改规则不会改变旧记录。

### class_score_periods

- `id`
- `class_id`
- `name`
- `starts_at`、`ends_at`
- `status`
- `created_at`

### class_score_ledger

- `id`
- `client_operation_id`（唯一，用于幂等与离线补传）
- `class_id`
- `student_id`
- `period_id`
- `rule_id`（可空）
- `rule_name_snapshot`
- `delta`
- `source`：`screen` 或 `teacher`
- `actor_user_id`（仅教师端内部审计，可空且不在班级流水界面显示）
- `batch_id`（可空）
- `reversal_of_id`（可空，并保证一条原记录最多被撤销一次）
- `client_created_at`
- `created_at`

服务端总分查询以流水求和为准；可增加按班级、周期和学生的索引，但不建立可独立改写的余额字段。

## 接口与实时同步

教师端接口继续使用登录令牌鉴权；教室端在现有绑定成功后获得仅限该班级的屏幕会话令牌，避免把绑定码直接作为每次写操作的长期凭证。

需要新增的接口组：

- 班级管理开关与设置。
- 学生名单及座位布局。
- 积分规则与积分周期。
- 单人、批量积分登记。
- 流水查询与撤销。
- 排行榜查询。

新增实时事件：

- 班级管理配置变化。
- 学生或座位更新。
- 积分规则更新。
- 新增、撤销积分流水。
- 当前积分与排行榜失效通知。

服务端只广播数据变化事件，客户端收到后更新局部数据；广播通知仍沿用现有 `class:<classId>` 房间和队列机制。

## 离线与幂等

- 教室端为每次操作生成 `client_operation_id`，写入本地待同步队列后再请求服务端。
- 网络正常时成功响应后移出待同步队列。
- 网络断开时允许继续登记，并明显显示“待同步 N 条”。
- 页面刷新或浏览器重启后从本地存储恢复队列。
- 重连后按原顺序补传；服务端对 `client_operation_id` 设置唯一约束，重复请求返回原结果，不重复加分。
- 本地界面可以乐观展示积分，但必须区分“待同步”与“已同步”。
- 若服务端因会员到期、班级关闭或学生归档拒绝同步，记录留在异常队列并要求教师处理，不静默丢弃。
- 教师端与教室端并发写入时均追加流水，不使用覆盖式总分更新，因此不存在最后写入覆盖前一笔的问题。

## 兼容与迁移

- 数据库迁移只新增字段和表，不改写现有通知、公告、绑定码与班级协作数据。
- 所有现有班级的 `management_enabled` 初始化为 0。
- 现有教室端绑定码和本地绑定状态继续有效。
- 未开启班级管理时，教师端和教室端的页面结构、接口调用和广播行为保持原样。
- 开启班级管理时自动创建默认积分规则与当前学期，教师可随后调整。
- 关闭模块不删除任何数据。
- 有积分或学生历史的班级采用归档，不再直接级联物理删除。

## 分阶段交付

### 第一阶段：统一班级大屏

- 班级管理开关。
- 学生名单与座位表。
- 积分规则与周期。
- 教室端和教师端加扣分。
- 排行榜、流水与撤销。
- 60 秒自动返回。
- 广播抢占与恢复。
- 实时同步、离线队列和幂等。
- 订阅权益与老用户兼容。

### 第二阶段：完整班级管理后台

- 考试成绩导入。
- 成绩分析与趋势。
- 学生个人档案。
- 小组管理与统计。
- 数据导入、导出和历史归档增强。

## 验收标准

### 功能

- 仅广播班级看不到任何积分入口，广播功能无回归。
- 开启班级管理后，大屏无需重新绑定即可出现三个入口。
- 教室端和教师端均可登记，流水来源显示正确。
- 单人、批量和撤销操作的总分与流水始终一致。
- 排行榜在今日、本周、本月和本学期四个范围内计算正确。
- 积分、排行榜和流水页 60 秒无操作后返回日常页；每次操作重置计时。
- 广播可从任意状态覆盖，结束后恢复原状态并重置计时。
- 模块关闭再开启后数据完整。

### 异常

- 断网后可继续登记，刷新页面后待同步记录仍在。
- 恢复网络后自动补传且不会重复计分。
- 教室端与教师端同时登记不会互相覆盖。
- 会员到期、班级关闭和学生归档时都有明确错误状态，不丢弃本地待同步记录。

### 视觉与设备

- 在 1024×768、1280×720 和 1920×1080 下检查日常页、座位表、快捷规则、排行榜、流水与广播覆盖。
- 触摸屏和鼠标均可完成连续登记、批量登记和撤销。
- 日常页不出现座位表、学生姓名、具体积分或排名。
- 积分默认静音，广播声音不被积分反馈干扰。

### 回归

- 班级绑定、自动重连、全屏、公告栏、通知队列、语音播报、快捷回复和本地通知历史全部通过原有测试。
- 新增数据库迁移、接口鉴权、幂等、撤销唯一性、周期统计、模块开关和订阅限制测试。
