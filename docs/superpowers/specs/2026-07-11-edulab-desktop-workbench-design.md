# 数学课件桌面工作台改版设计

## 目标

让数学课件在桌面端呈现为录屏中的满屏三栏工作台，同时保留移动端可用性；减少生成页留白，并提高数学解答可靠性。

## 已确认问题

1. 函数题模板把 `.wrap` 固定为 `max-width: 560px`，所有内容纵向排列，宽屏必然大面积留白。
2. 数学生成主页在成功后只显示一个链接卡片，右侧主要区域没有承载课件预览。
3. 当前函数题先由 Flash 生成单次解答，之后的图表和讲解都把这份结果当作“已验证解答”；本次样例中存在明显代入错误，错误会沿链路放大。
4. “重新生成”没有清楚提示会再次消耗 75 积分。

## 方案

### 生成后的函数课件

- 桌面宽度大于 1024px 时占满视口，使用三栏：
  - 左栏：题目与参数控制台；
  - 中栏：完整分步解析，可独立滚动；
  - 右栏：函数图像，占据最大面积。
- 页面本身不做纵向长页；三栏分别内部滚动。
- 图像卡顶部显示“函数图像 · 动态观察”和重置按钮。
- 所有步骤同时展示，避免为了看前后推理频繁翻页。
- 1024px 以下改为双栏，760px 以下才改为单栏长页。

### 数学生成主页

- 生成成功后，右侧用 iframe 直接预览课件并占满可用高度。
- 保留“新窗口打开”和“复制链接”，不再把裸链接作为视觉主角。
- “重新生成”明确标注再次消耗 75 积分并二次确认。

### 数学正确性

- 课件结构仍使用 `deepseek-v4-flash`，保证速度和成本。
- 数学求解改为 `deepseek-v4-pro`，开启 thinking mode，推理强度设为 `high`，输出上限 18000。实测 `max` 可能把预算主要耗在思考过程，最终正文为空；`high` 能稳定返回完整答案。
- 增加一次独立复核：逐小问检查结论、代入、必要条件和最终答案；复核输出成为课件唯一依据。
- 复杂题的进度提示改为“识别题目 → 深度求解 → 复核答案 → 生成课件”。

## 本次不扩大的范围

- 不重做立体几何和解析几何引擎；它们已有桌面工作台布局。
- 不改变积分价格。
- OCR 识别结果确认、错题反馈与课件收藏作为后续高优先级改进建议，本次先不扩接口。

## 验收

- 1440×900 桌面视口下，函数课件三栏铺满，画板占至少 45% 宽度，页面无大面积空白。
- 390px 手机视口下为单栏，题面、图像、解析均可读。
- 生成主页成功态出现内嵌课件预览。
- 样例题使用 V4 Pro 深度推理与复核，不再沿用截图中的错误结论。
- 自动测试、脚本语法、线上页面与服务健康检查全部通过。
