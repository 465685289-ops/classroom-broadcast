# 腾讯云精品语音接入设计

## 目标

把班级大屏目前粗糙、设备差异明显的百度演示语音，替换为腾讯云“标准语音合成—精品音色”。首版固定使用情感女声“智瑜”（VoiceType `101001`），老师无需在页面选择音色。

## 用户体验

- 老师发送通知后，大屏仍按原来的节奏展示并播报，不增加操作步骤。
- 同一条通知设置多次播报时，只合成一次音频，在大屏本地重复播放，避免重复计费和等待。
- 腾讯云临时不可用、服务器未配置密钥或教室断网时，自动回退到浏览器中文语音，不阻断通知展示。
- 不再从浏览器直连百度演示接口，避免声音来源不稳定，也避免通知文字额外发送给无正式授权的第三方接口。

## 技术方案

采用“浏览器 → 自有服务端 `/api/tts` → 腾讯云 TTS”的服务端代理模式：

1. `public/screen.html` 向自有服务端提交播报文字和班级绑定码。
2. `tts-routes.js` 完成鉴权、限流、长度校验和缓存。
3. `tencent-tts.js` 通过腾讯云官方 Node.js TTS SDK 调用 `TextToVoice`。
4. 服务端把腾讯返回的 Base64 音频解码为 MP3 二进制，再返回大屏。
5. 大屏解码播放；失败时使用 `speechSynthesis` 本地兜底。

选择官方产品级 SDK `tencentcloud-sdk-nodejs-tts`，不引入体积很大的全产品 SDK，也不自行维护签名算法。腾讯密钥只从服务器环境变量读取，绝不写入 Git 或前端。

## 配置

新增环境变量：

- `TENCENT_TTS_SECRET_ID`：腾讯云 API SecretId。
- `TENCENT_TTS_SECRET_KEY`：腾讯云 API SecretKey。
- `TENCENT_TTS_REGION`：地域，默认 `ap-guangzhou`。
- `TENCENT_TTS_VOICE_TYPE`：音色编号，默认 `101001`（智瑜）。

建议创建只允许调用语音合成的 CAM 子用户密钥，不使用腾讯云主账号永久密钥。`.env.example` 只记录变量名和示例，不记录真实凭证。

## 接口契约

`POST /api/tts`

请求：

```json
{
  "text": "请第一小组到操场集合。",
  "bind_code": "ABC123"
}
```

规则：

- 教室端需提供有效班级绑定码，老师端可使用登录凭证。
- 空文本返回 `400`，无凭证返回 `401`，超过 150 个汉字的文本返回 `413`。
- 同一 IP 每分钟最多 20 次，超限返回 `429`。
- 未配置腾讯云密钥返回 `503`；腾讯云调用失败返回 `502`，响应不得泄露密钥和上游内部详情。
- 成功返回 `audio/mpeg`，并标记私有缓存头。

## 缓存与成本

服务端使用有上限的内存 LRU 缓存，以“音色编号 + 文本”作为键。缓存最多 200 条，进程重启后自然清空，不向磁盘写学生或通知内容。同一通知的多次播报直接复用一个音频缓冲区。

## 验证

- 单元测试：真实执行客户端参数构造和 Base64 解码，仅替换外部腾讯网络调用。
- 路由测试：用真实 Express 服务验证鉴权、长度、限流、缓存、成功音频和安全错误。
- 页面测试：执行大屏内联脚本，确认首选 `/api/tts`、百度演示接口已移除、失败回退浏览器语音、音量增益不再失真。
- 完整回归：串行运行 `npm test`。
