# 班级广播首次开通引导设计

## 目标

首版只服务一类核心用户：第一次使用班级广播的班主任。目标不是讲完全部功能，而是在三分钟内帮助老师完成“建立班级 → 连接教室大屏 → 发出第一条有声音的通知”，让老师亲眼看到、亲耳听到产品价值。

现有登录后的默认页是“发布通知”。新老师还没有班级时，发送按钮无法使用，却看不到明确的下一步；引导要消除这段空白，而不能再增加一套冗长教程。

## 范围与非目标

本功能仅改造班级广播教师端 `teacher.html` 的首次开通路径，复用既有账号、会员、班级、固定教室链接、Socket.IO 在线状态、腾讯云语音和通知接口。

本期不新增另一套登录、不要求导入花名册、不要求开启班级积分管理、不修改课程表数据、不替科任老师设计“加入协作班级”的完整流程，也不改变已有老师的班级、通知、会员或大屏绑定。

## 选择的交互形式

采用可暂停的三步清单，而非强制逐页教学弹窗或隐藏式帮助入口。

- 强制向导会妨碍老师在手机与教室电脑之间切换；本产品的首次配置天然跨设备。
- 仅放一个帮助按钮容易被忽略，不能解决“刚登录、没有班级、不能发送”的卡点。
- 三步清单常驻于发布页顶部，完成一项自动打勾；老师可以暂时收起，下一次仍从未完成步骤继续。

## 班主任的首次使用主线

### 第 1 步：建立我的第一个班级

引导卡标题为“先把第一块教室大屏开通”，进度显示 `0 / 3`。第一个按钮“新建班级”跳转至现有“班级管理”页，并高亮现有学段和班级名称表单。老师照常选择学段、填写例如“八年级一班”、点击“新增”。

班级创建成功后，系统把这个班记为本次开通目标，回到发布页并自动选中该班；第 1 步变为完成。班主任可继续正常创建其他班级，但引导始终围绕第一个开通班级，不把多个班混在一条新手路径里。

### 第 2 步：连接教室大屏

卡片展示目标班级名称及两个动作：

- “复制固定教室链接”：复用现有固定链接，形如 `/screen.html#bind=ABC123`；手机端可复制后通过常用方式发送到教室电脑。
- “我正在教室电脑上设置”：在当前设备新窗口打开同一固定链接，方便老师直接在教室电脑操作。

旁边用一句话说明：“在教室电脑打开后收藏为书签或设为首页，以后不用再输绑定码。” 大屏成功绑定后，服务端已有的在线更新会让教师端自动显示“教室大屏已连接”，无需老师手动刷新。

复制链接本身不算完成；只有教室端真正发出成功绑定事件，才完成第 2 步。若暂时不在教室，老师可以收起引导，进度不丢失。

### 第 3 步：发送第一条测试通知

点击“发送一条测试通知”后回到发布页，自动选择目标班级，并填入：

> 测试通知：班级广播已连接成功。

默认方式是“文字＋语音”，播报次数为 `1`。这是产品核心卖点，测试通常由老师在非上课时间完成；如需静音，老师可自行切换为“仅文字（静音）”。老师可修改文字，或暂时不发送。只要该班主任成功发出本班的第一条通知，无论是预填测试文字还是真实通知，第 3 步都完成。

## 完成后的状态

完成三步后，不让引导完全消失。卡片缩小为：

> 教室大屏已开通
> 下一步可设置课程表、邀请科任老师协作。

卡片提供“设置课程表”和“班级管理”入口，但它们都不是首次开通的必经步骤。已完成的班主任不会再看到阻塞发布页的大卡片。

## 跨设备状态与数据模型

进度必须保存在服务端 SQLite，不能只写入手机浏览器。建议新增独立表 `classroom_onboarding`：

```sql
CREATE TABLE IF NOT EXISTS classroom_onboarding (
  user_id TEXT PRIMARY KEY,
  version INTEGER NOT NULL DEFAULT 1,
  first_class_id TEXT,
  screen_connected_at TEXT,
  first_notification_id INTEGER,
  first_notification_at TEXT,
  updated_at TEXT NOT NULL
);
```

`first_class_id` 在班主任创建第一班时首次写入；后续创建其他班不覆盖它。教室大屏绑定成功时，仅当绑定班属于该班主任且等于 `first_class_id`，写入 `screen_connected_at`。班主任向该班成功持久化第一条通知时，写入通知 ID 和时间。三种写入均为幂等：已经有值时不覆盖，避免重复连接或重复发送改写首次完成记录。

`GET /api/classroom-onboarding` 返回目标班级、当前在线台数、三步完成状态和下一步。接口只返回当前登录班主任自己的目标班，协作老师不借此读取班主任的进度。历史版本没有保存过“大屏曾绑定”的记录：对于已有成功通知的班主任，首次读取时以最早一条本人通知所属班级补齐目标班，并把通知时间同时作为“已连过大屏”和“已发首条通知”的历史里程碑；只有班级、没有通知的既有班主任则从第 2 步开始。没有班级则从第 1 步开始。

## 异常与状态文案

- 目标班级已建立但没有大屏在线：显示“链接已准备好，教室电脑打开一次即可连接”。
- 已连接过、当前大屏关机或断网：保留“已开通”，附加“当前大屏离线”；绝不把第 2 步退回未完成。
- 通知发送失败：保留老师已输入的正文，不标记第 3 步完成，并显示既有错误提示。
- 教室端临时绑定错误：沿用固定链接与保存绑定的既有保护，不清除大屏侧绑定信息。
- 老师收起卡片：仅收起本次页面的展开状态，不写“已完成”；下次登录仍能继续。

## 技术边界

新 API 域新增 `classroom-onboarding-routes.js`，采用现有 installer 模式，在 `server.js` 集中安装；路由使用 `middleware.js` 的 `userAuth`、`state.js` 的共享内存状态和 `db.js` 的 SQLite helper，不建立回环依赖。

创建班级、教室端 `bind-success`、`POST /api/notify` 三个现有生命周期点负责写入进度；业务主操作不能因进度记录失败而被阻断，只记录服务端安全日志。教师端只调用受鉴权保护的读接口，不向前端暴露数据库或其他班级信息。固定链接的 `#bind=` 哈希仍不发送到 HTTP 服务端。

## 验收标准

1. 新班主任登录后，在发布页看见三步开通清单；没有班级时，不再只能看到禁用的发送按钮。
2. 建立班级后，目标班被自动选中，刷新、换手机或重新登录后仍保留完成进度。
3. 复制或打开固定链接不算完成；教室端实际绑定后，教师端在在线更新到达时自动完成第 2 步。
4. 测试通知默认“文字＋语音”、播报 1 遍；第一次成功发送真实通知也能完成第 3 步。
5. 大屏后来离线不会撤销开通状态；通知失败不会清空正文或误标记完成。
6. 已有班主任按真实使用历史展示恰当状态；协作老师和未授权请求不能读取别人的引导状态。
7. 390px 手机宽度没有页面横向溢出，桌面端卡片不挤压现有发布表单。
8. 完整 `npm test` 串行通过；补充服务端、页面和跨设备恢复测试；本地浏览器验收覆盖“新账号 → 建班 → 教室端绑定 → 语音测试通知”。

## 上线边界

本文档只定义功能与实施方案，尚未修改生产功能代码、未上传服务器、未重启服务。完成开发、测试、Git 合并后，仍需按项目文件式部署流程备份 SQLite 与变更文件、发布、重启并做公网验收，才能标记为“已上线”。
