# 教室端六项修复设计

## 目标

在不改变现有暖棕视觉语言的前提下，修复教室端空闲页在常见投影分辨率上的裁切，并让刷新重连、全屏、长通知和本地历史符合页面文案承诺。

## 方案选择

选择“高度响应式压缩 + 小范围状态修复”，不重做整个教室端。

- 方案 A（采用）：保留双栏结构，在屏幕高度不超过 800px 时压缩字号、间距和内边距；在窄屏时把二维码卡固定到左侧卡片右半区。改动小，能覆盖 1024×768、1280×720 和大屏。
- 方案 B：允许左侧卡片滚动。实现最小，但教室大屏出现滚动条且二维码仍可能不在首屏，不采用。
- 方案 C：彻底重做为新栅格。视觉风险和回归范围过大，不采用。

## 六项行为

1. 二维码卡：不再被 `overflow:hidden` 裁切；二维码增大并保留更宽白边；窄屏不再直接隐藏。
2. 时钟：使用 `clamp()` 与高度媒体查询，禁止换行，1024px 宽度下保持完整。
3. 自动绑定：Socket 首次连接时，只要存在 `savedBind` 就提交绑定码；无效时返回绑定页并给出可见错误。
4. 全屏：绑定按钮在用户手势内尝试进入全屏；屏幕页提供明确的“全屏/退出全屏”按钮；不再使用会被第一次点击提前消耗的单次监听器。
5. 长通知：正文最小字号保持 28px，超长内容允许在气泡内滚动，避免为了塞进一屏缩成小字。
6. 今日计数与历史：按班级写入 `localStorage`；刷新后恢复最近 50 条记录；跨日自动将“今日通知”归零；解除绑定时清除本机对应班级状态。

## 验证

- 自动化：新增教室端静态回归测试，并运行现有全部测试。
- 视觉：检查 1024×768、1280×720、1920×1080；测量二维码卡边界、时钟溢出和窄屏二维码可见性。
- 线上：备份后部署静态页面，确认 HTTP、关键代码标记与服务日志正常。
